# InGit: Методология интегрированной системы управления версиями и проектами

## 1. Введение

### 1.1. Концепция проекта

**InGit** (Integrated Git) — это комплексная система управления версиями, документацией и проектами, объединяющая принципы распределенного контроля версий (Git), систем управления проектами (PM) и ERP-систем. Ключевая особенность — **полноценная работа в оффлайн-режиме** с возможностью синхронизации при наличии сети.

### 1.2. Целевое назначение

- **Управление версиями** кода, документации, конфигураций
- **Управление проектами** с планированием, трекингом задач, ресурсами
- **Управление знаниями** и личным/корпоративным архивом
- **Финансовый учет** и бюджетирование проектов
- **Автоматизация рабочих процессов** через hooks и скрипты
- **Безопасное хранение** с шифрованием критичных данных

### 1.3. Ключевые принципы

1. **Offline-first** — все функции доступны без интернета
2. **Decentralized** — данные хранятся локально, синхронизация опциональна
3. **Secure by design** — встроенное шифрование и контроль доступа
4. **Extensible** — модульная архитектура с плагинами
5. **Cross-platform** — Desktop (Linux/Windows/macOS), Android, Web-интерфейс

### 2.2. Анализ решений

#### Git (стандарт)
**Преимущества:**
- Полностью децентрализован
- Универсальный стандарт
- Мощная система ветвления и слияния

**Недостатки:**
- Только контроль версий, без UI для управления проектами
- Крутая кривая обучения
- Нет встроенного управления задачами/документацией

#### GitLab Community Edition
**Преимущества:**
- Полнофункциональная DevOps-платформа
- Issues, Wiki, CI/CD из коробки
- Хорошая интеграция инструментов

**Недостатки:**
- Требует постоянно работающий сервер
- Высокие требования к ресурсам (RAM 4GB+)
- Ограниченная работа оффлайн (только git pull/push)
- Сложность установки на NAS

#### Gitea
**Преимущества:**
- Легковесный (написан на Go)
- Простая установка
- Подходит для NAS (низкое потребление ресурсов)

**Недостатки:**
- Требует запущенный сервер для веб-интерфейса
- Нет полноценного desktop-приложения
- Ограниченная оффлайн-функциональность

#### Fossil
**Преимущества:**
- Все-в-одном: VCS + Wiki + Bug tracking + Форум
- Один исполняемый файл
- Хорошая оффлайн-работа

**Недостатки:**
- Менее распространен чем Git
- Нет мобильных клиентов
- Ограниченная экосистема инструментов
- Нет управления проектами в стиле ERP

### 2.3. Выводы из анализа

**Ни одно из существующих решений не обеспечивает:**
1. Полноценную работу в оффлайн-режиме с GUI
2. Интеграцию управления версиями + управления проектами + финансов
3. Нативные приложения для Desktop и Android
4. Оптимизацию для домашнего NAS
5. Встроенное шифрование данных

**InGit должен заполнить эту нишу**, объединив лучшие практики.

### 3.2. Компоненты системы

#### 3.2.1. Уровень хранения (Storage Layer)

**A. Git-репозитории**
- Хранение версионируемых файлов
- История изменений
- Ветвление и слияние

**B. Реляционная БД (SQLite primary, PostgreSQL optional)**
- Метаданные проектов
- Задачи и связи между ними
- Пользователи и права доступа
- Финансовые записи
- Индексы для быстрого поиска

**C. Зашифрованные контейнеры**
- Критичные данные (финансы, персональная информация)
- Использование age/GPG для шифрования
- Ключи хранятся отдельно

**D. LFS-хранилище**
- Большие бинарные файлы
- SHA256-манифесты для проверки целостности

#### 3.2.2. Движок управления версиями (Git Core)

**Базируется на libgit2:**
- Полная совместимость с Git
- Программный доступ к Git API
- Встроенная поддержка hooks
- Пользовательские diff/merge стратегии

**Расширения:**
- Автоматическая обработка YAML-метаданных
- Валидация перед коммитом
- Интеграция с системой задач

#### 3.2.3. Движок управления проектами (PM Engine)

**Функциональность:**
- Создание и управление проектами
- Задачи с приоритетами, метками, исполнителями
- Диаграммы Gantt
- Kanban-доски
- Отслеживание времени
- Зависимости между задачами
- Вехи (milestones)

**Интеграция с Git:**
- Привязка коммитов к задачам
- Автоматическое закрытие задач через commit messages
- Связь веток с задачами

#### 3.2.4. API-слой

**REST API:**
- CRUD операции для всех сущностей
- Аутентификация через JWT
- Rate limiting

**GraphQL API:**
- Гибкие запросы для клиентов
- Subscription для real-time обновлений
- Batch operations

#### 3.2.5. Клиентские приложения

**Desktop GUI:**
- Технологии: Electron + React ИЛИ Qt + C++
- Полный доступ к локальным репозиториям
- Оффлайн-первый дизайн
- Синхронизация в фоне

**Web Interface:**
- SPA на React/Vue
- Подключение к локальному серверу или NAS
- Responsive design

**Android App:**
- React Native или Flutter
- Просмотр репозиториев
- Базовое редактирование
- Синхронизация через WiFi/Mobile

### 3.3. Режимы развертывания

#### Режим 1: Standalone Desktop
```
[Desktop App] ←→ [Local SQLite + Git Repos]
```
- Полностью автономная работа
- Все данные на локальном диске
- Синхронизация через USB или облако (опционально)

#### Режим 2: Домашний NAS
```
[Desktop/Mobile Clients] ←WiFi→ [NAS Server]
                                  ├─ InGit Server
                                  ├─ SQLite/Postgres DB
                                  └─ Git Repos
```
- Централизованное хранение на NAS
- Доступ через локальную сеть
- Оффлайн-кэш на клиентах

#### Режим 3: Гибридный
```
[Desktop] ←→ [Local Repos] ←sync→ [NAS/Cloud Repos]
```
- Локальная копия для оффлайн-работы
- Периодическая синхронизация с NAS/облаком
- Conflict resolution

        'task': ['type', 'title', 'status', 'assignee'],
        'expense': ['type', 'title', 'date', 'amount', 'category']

    with open(file_path) as f:
        data = yaml.safe_load(f)

### 4.4. Workflow для разных сценариев

#### Сценарий 1: Разработка ПО
1. Создать проект в InGit
2. Инициализировать структуру репозитория
3. Создать задачи в `70_tasks/backlog/`
4. Переместить задачу в `in-progress/` при начале работы
5. Коммитить код с префиксом `[#task-id]`
6. После завершения задача автоматически перемещается в `done/`

#### Сценарий 2: Ведение документации
1. Добавить новый документ в `30_documents/`
2. Создать YAML-карточку с метаданными
3. Коммит с описанием изменений
4. Периодическая генерация сводок

#### Сценарий 3: Личный финансовый учет
1. Добавить записи о расходах/доходах в `40_finance/`

3. Автоматическая генерация отчетов (месячные, годовые)
4. Синхронизация с NAS в зашифрованном виде

## 5. Безопасность

### 5.1. Многоуровневая защита

#### Уровень 1: Шифрование данных
- **age** для файлов (современная замена GPG)
- **Прозрачное шифрование** папок (например, `40_finance/`)
- **Шифрование в покое** для БД (SQLCipher)

#### Уровень 2: Контроль доступа
- **Аутентификация**: пароль + 2FA (TOTP)
- **Авторизация**: роли (owner, admin, developer, viewer)
- **Аудит**: лог всех операций

#### Уровень 3: Сетевая безопасность
- **TLS/SSL** для всех сетевых подключений
- **Firewall rules** для NAS-сервера
- **VPN** для удаленного доступа

### 5.2. Резервное копирование

#### Стратегия 3-2-1
- **3** копии данных
- **2** разных носителя (NAS + внешний HDD)
- **1** копия вне площадки (облако зашифрованное)

#### Автоматизация
- Ежедневные инкрементные бэкапы
- Еженедельные полные бэкапы
- Проверка целостности через SHA256

## 6. Преимущества InGit

### 6.1. По сравнению с традиционными VCS

| Преимущество | Описание |
|--------------|----------|
| **Unified Workspace** | Код + документы + задачи + финансы в одном месте |

| **Offline-capable PM** | Управление проектами без интернета |
| **Native encryption** | Шифрование встроено, не требует внешних инструментов |
| **Desktop-first** | Полноценное GUI-приложение, не только веб |

### 6.2. По сравнению с PM-системами (Jira, Asana)

| Преимущество | Описание |
|--------------|----------|
| **Owns your data** | Данные локально, не в чужом облаке |
| **Works offline** | Не требует постоянного подключения |
| **Version controlled** | История всех изменений задач/документов |
| **Developer-friendly** | Git workflow + CLI + API |
| **No subscription** | Бесплатно, open-source |

### 6.3. По сравнению с ERP (Odoo, ERPNext)

| Преимущество | Описание |
|--------------|----------|
| **Lightweight** | Не требует мощного сервера |

| **Git integration** | Нативная поддержка версионирования |
| **NAS-optimized** | Идеально для домашнего/малого бизнеса |

## 7. Ограничения и компромиссы

### 7.1. Известные ограничения

1. **Масштабируемость**: не предназначена для корпораций с 1000+ пользователей
2. **Real-time collaboration**: ограничена по сравнению с облачными решениями
3. **Мобильный клиент**: только базовый функционал (пока)
4. **Сложность настройки**: больше чем у простых решений

### 7.2. Целевая аудитория

✅ **Подходит для:**
- Фрилансеров и индивидуальных разработчиков
- Малых команд (2-20 человек)
- Домашнего использования (личный архив, финансы)
- Компаний, требующих контроль над данными
- Проектов с ограниченным интернетом

❌ **Не подходит для:**
- Крупных корпораций с распределенными командами
- Проектов, требующих real-time коллаборацию 24/7
- Пользователей без базовых навыков Git/CLI

## 9. Заключение

**InGit** представляет собой амбициозную попытку объединить лучшие практики:
- Распределенного контроля версий (Git)
- Управления проектами (PM-системы)
- Личного управления знаниями (PKM)
- Финансового учета (домашняя бухгалтерия)

Ключевая ценность — **возможность полноценно работать оффлайн** с последующей синхронизацией, при этом сохраняя все преимущества современных DevOps и PM инструментов.

Система спроектирована как **мета-приложение**, которое может заменить десяток разрозненных инструментов, обеспечивая единую среду для управления жизненным циклом проектов и личной информации.
